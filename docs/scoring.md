# Оценивание команд

Обязательная часть остаётся небольшой: три товара, корзина и сумма. Дополнительные задачи добровольные. Максимум — **100 баллов**: база 20, интерфейс 30, backend 30, качество 10, деплой 10.

## Правила

1. Ведущий объявляет таблицу всем командам до начала соревнования. Если работа уже началась, согласуйте общий момент начала оценивания и одинаковый срок сдачи; не применяйте новые условия задним числом к вчерашним результатам.
2. Команда указывает в issue ID выполненных задач и финальный commit. Ментор проверяет именно эту версию. Публичный сайт и архив должны ей соответствовать.
3. За строку начисляется полный балл, если прошли все перечисленные в ней проверки; иначе 0. Проверять стоит на простых тестовых данных, а не на удачно подобранном единственном примере.
4. Для победы в общем зачёте обязательны все четыре пункта M1–M4. Остальные команды тоже сдают работу и получают обратную связь.
5. Бонусы складываются. F4/F5 и B2 можно получить вместе: первые проверяют интерфейс, второй — реальную обработку на сервере. Кнопка без работающей логики и захардкоженный ответ для одного запроса не засчитываются.
6. AI и помощь менторов разрешены. Участники объясняют, как работает показанная функция и где находится её код. Количество промптов, строк кода и платных сервисов не оценивается.
7. Неработающая дополнительная функция не обнуляет другие баллы. Но если она сломала корзину или сумму в итоговой версии, соответствующий пункт обязательного минимума не проходит.

## Backend — 30 баллов

Локальная демонстрация полноценна. Платное размещение и публичный сервер не требуются. Проверяйте HTTP-запросы через Network в браузере или curl/Postman.

| ID | Баллы | Проверка |
|---|---:|---|
| B1 | 5 | GET /api/products возвращает JSON минимум с тремя товарами и стабильными ID; интерфейс получает каталог оттуда; изменение серверных данных видно после обновления страницы |
| B2 | 5 | Поиск и категория передаются в API; сервер возвращает отфильтрованный результат, включая пустой список; UI показывает его. Скачивание всех товаров с фильтрацией только в браузере не засчитывается |
| B3 | 5 | POST /api/orders создаёт заказ и возвращает ID и сумму; сервер сам определяет цены; подмена цены клиентом не уменьшает итог; пустой заказ, неизвестный товар и количество 0, −1 или 1.5 отклоняются с 4xx без создания заказа |
| B4 | 5 | Товары и созданные заказы хранятся в базе; после остановки и запуска сервера прежний заказ можно прочитать через API или команду из README. Запуск не стирает базу и не заменяет её начальными данными |
| B5 | 5 | Заказ уменьшает остаток; превышение остатка отклоняется. При остатке 1 два одновременных заказа не могут оба завершиться успешно. Неуспешный заказ не меняет остатки других товаров |
| B6 | 5 | Запрос изменения каталога без токена и с неверным токеном получает 401/403 и не меняет данные; с верным — меняет. Токен читается из окружения, отсутствует в Git и публичных файлах; показаны команды для проверки |

B4 и B5 проверяются вместе с рабочим созданием заказа B3. За одну только установленную БД, пустой endpoint или запущенный сервер баллы не начисляются.

## Качество и деплой — 20 баллов

| ID | Баллы | Проверка |
|---|---:|---|
| Q1 | 5 | Есть минимум 3 автоматические проверки функций магазина, включая обычный и ошибочный/граничный сценарии. Они запускаются одной командой и проходят на сдаваемом commit. Хотя бы одна проверка падает при намеренной поломке проверяемой логики в копии проекта. Проверки упаковки из шаблона не заменяют тесты магазина |
| Q2 | 5 | Ментор запускает чистую копию по README: указаны версии инструментов, зависимости, команды и тестовые данные; нет необходимости править исходники или получать неописанные секреты. Для backend есть .env.example и подготовка базы, если она используется |
| D1 | 5 | HTTPS-сайт открывается без входа на другом устройстве; обязательная часть M1–M4 работает. Указаны URL и commit. Ссылка на исходники вместо сайта не считается деплоем |
| D2 | 5 | После push видимого изменения в main публикация запускается автоматически, workflow проходит и тот же публичный URL показывает изменение. Готовый workflow из шаблона разрешён, но его работу нужно продемонстрировать; повторный ручной запуск не засчитывается как автодеплой |

D2 требует рабочего D1. Деплой статической версии достаточен даже при наличии локального backend. Собственный домен, платный хостинг и запуск backend в облаке не дают отдельных баллов.

## Как выбрать победителя

Побеждает команда с выполненными M1–M4 и наибольшей суммой. При равенстве сравните сумму Q1+Q2, затем B1–B6. Если равенство осталось, объявите совместное место: скорость и впечатление от оформления не используются как скрытые критерии.

Можно отдельно отметить лучший интерфейс по F1–F10 и лучший backend по B1–B6. При равных баллах в номинации — совместное место.

## Лист проверки ментора

Скопируйте в комментарий к сдаче. Для каждого заявленного ID укажите «зачтено / не зачтено» и короткий результат проверки. Итог подтверждает ментор, а не сама команда.

```text
Команда / дата:
Финальный commit:
Проверил:
M1–M4: __ / 20
F1–F10: __ / 30
B1–B6: __ / 30
Q1–Q2: __ / 10
D1–D2: __ / 10
Итого: __ / 100
Обязательный минимум полностью выполнен: да / нет
Проверенные ID и замечания:
```
