# Самостоятельный деплой

Деплой — публикация сайта в интернете. За рабочую HTTPS-ссылку и показ обновления команда получает отдельное достижение. Если публикация не удалась, сдайте локальную версию и ZIP: основной результат не пропадает.

Для основного пути нужны готовая папка сайта и аккаунт одного участника. Выбирайте бесплатный план. Если сервис предлагает оплату или не открывается в сети площадки, переходите к запасному пути или зовите ментора. Не тратьте на выбор хостинга больше 10 минут.

## Путь 1: Cloudflare Pages, загрузка файлов

1. Войдите в Cloudflare, откройте **Workers & Pages** и создание проекта Pages с прямой загрузкой (**Drag and drop / Upload assets**). Названия кнопок могут немного отличаться.
2. Назовите проект, например `itmo-team07-shop`. Если имя занято, добавьте свой суффикс.
3. Загрузите готовую папку или ZIP, в корне которого находится `index.html`.
4. Выполните публикацию и дождитесь успешного статуса.
5. Откройте выданный адрес вида `https://<project>.pages.dev` на другом устройстве или в приватном окне.
6. Измените заметный текст, например добавьте «Версия 2», и подготовьте файлы заново.
7. В **существующем проекте** создайте новую production-публикацию. Проверьте, что тот же основной адрес показывает новую версию. Preview-ссылка не заменяет основной адрес.

У каждого проекта собственный hostname, поэтому браузерное хранилище команд разделено. Для загрузки через панель действуют ограничения до 1 000 файлов и 25 MiB на один файл. Direct Upload не запускает вашу сборку и не компилирует папку Pages Functions. Переключить такой проект на Git integration впоследствии нельзя: для этого потребуется новый проект.

Источник: [Cloudflare Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/). Общие квоты — в [Pages limits](https://developers.cloudflare.com/pages/platform/limits/).

## Путь 2: GitHub Pages

**Если вы взяли наш шаблон Go, Java или C#:** в нём уже есть workflow `Publish site`. В Settings → Pages выберите Source: GitHub Actions, затем Actions → Publish site → Run workflow. Он публикует `site/`; копировать файлы в `docs/` не требуется. Для обновления сделайте push и повторно запустите workflow. Подробности и включение автодеплоя — в README шаблона.

Следующие шаги нужны для проекта **без готового workflow**. Выберите один способ настройки Pages: Actions либо публикация из ветки.

Подходит для публичного репозитория на GitHub Free. Это размещение статики: Go, Java и C# как серверные процессы здесь не работают.

1. Подготовьте отдельный публичный репозиторий для сайта либо используйте репозиторий команды. Для простого варианта разместите готовый `index.html` и ресурсы в папке `docs/` ветки `main`. Здесь `docs/` — папка сайта, не документация из этого гайда.
2. Добавьте в эту папку пустой файл `.nojekyll`, если публикуете готовые файлы без Jekyll.
3. В **Settings → Pages → Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/docs`, сохраните.
4. Дождитесь завершения публикации. Адрес будет показан в Settings → Pages, обычно это `https://<owner>.github.io/<repo>/`.
5. Проверьте CSS, JS и картинки. Для подпапки используйте относительные пути; `/styles.css` ищет файл в корне домена и может дать 404.
6. Для обновления замените готовые файлы в `docs/`, удалите устаревшие и сделайте commit/push. Дождитесь новой публикации и откройте прежнюю ссылку.

Сайты `org.github.io/team01` и `org.github.io/team02` имеют **одинаковый origin**. Разделяйте ключи `localStorage` номером команды. Это предотвращает случайные пересечения, но не даёт изоляции между сайтами: для неё используйте отдельные hostnames, например проекты Pages из первого пути.

Источник: [создание GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site), [выбор источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site). Это учебное демо без настоящих покупок; учитывайте [ограничения и назначение GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

## Если оба пути недоступны

Можно использовать [Netlify Drop](https://docs.netlify.com/start/quickstarts/netlify-drop-quickstart/): загрузить готовую папку сайта, получить ссылку и закрепить проект в своём аккаунте для управления. Для обновления открывайте существующий проект, а не создавайте новый. Перед работой проверьте текущие условия Free-плана в панели. Не полагайтесь на анонимную временную ссылку как на постоянную сдачу.

## Проверка публичного сайта

- Ссылка открывается без входа в аккаунт хостинга, по HTTPS.
- Каталог, картинки, стили и JavaScript загрузились.
- Добавление, изменение количества и промокод работают.
- После перезагрузки страницы корзина сохраняется. В приватном окне изначально пустая корзина — нормально.
- В браузерной консоли нет ошибок, мешающих работе.
- После повторной публикации основной адрес остался прежним.

`localStorage` локального адреса не переносится на публичный сайт. Также он не переносится между preview-адресом и production-адресом.

## Откат и версии

Перед обновлением сохраните предыдущий ZIP и commit ID. Самый универсальный откат — повторно опубликовать предыдущую сборку в том же проекте. Для GitHub Pages можно восстановить прежнее содержимое `docs/` новым коммитом. Не переписывайте общую Git-историю ради отката.

Если хостинг выдаёт отдельную ссылку на конкретный deployment, приложите её вместе с основной. Не считайте основной URL неизменяемой версией: он обновляется. Для воспроизводимости сдайте commit ID и соответствующий ZIP.

## Дополнительный респект

Автодеплой из Git, проверенный откат или собственный домен — самостоятельные дополнительные задачи. Для домена можно изучить [DigitalPlat FreeDomain](https://github.com/DigitalPlatDev/FreeDomain); регистрация и распространение DNS могут занять время. Не откладывайте рабочую ссылку провайдера ради красивого домена.

Сервисы и условия проверены по документации 9 ноября 2026 года. Бесплатные квоты и доступность могут меняться. Сайт существует, пока доступен аккаунт и проект соблюдает условия сервиса; гарантированный срок хранения организатор не предоставляет. Сохраните локальную копию исходников и сборки.
