# Самостоятельный деплой на GitHub Pages

Деплой — публикация сайта в интернете. Это дополнительное достижение: обязательную часть можно сдать локально. Для учебного статического сайта используем бесплатный GitHub Pages и публичный репозиторий.

## Из нашего шаблона: по кнопке

В шаблонах Go, Java, C# и Python уже есть workflow `Publish site`.

1. Создайте **свой** репозиторий через **Use this template → Create a new repository**. В нём должны лежать папка `site/` и файл `.github/workflows/pages.yml`.
2. Загрузите изменения вашего магазина в репозиторий (commit и push).
3. Откройте **Settings → Pages → Build and deployment → Source**, выберите **GitHub Actions**. Если настроек нет, обратитесь к владельцу репозитория или ментору.
4. Откройте **Actions → Publish site → Run workflow**, выберите ветку `main` и нажмите зелёную кнопку запуска.
5. Дождитесь зелёного результата. Адрес сайта появится в выполненном workflow и в **Settings → Pages**.
6. Откройте ссылку в приватном окне или на телефоне. Обычно она выглядит как `https://<owner>.github.io/<repo>/`.

Workflow публикует **содержимое `site/`**. ZIP загружать на Pages не требуется; он нужен для сдачи и сохранения сборки. Исходники серверов Go, Java, C# и Python здесь не запускаются.

## Обновление по той же ссылке

1. Измените заметный текст в `site/index.html`.
2. Сохраните изменения коммитом и отправьте их в GitHub.
3. Снова запустите **Publish site → Run workflow**.
4. После успешного завершения откройте прежний адрес и проверьте новый текст.

Для автоматической публикации при push добавьте событие `push` в workflow по примеру из README вашего шаблона. Это дополнительная задача.

## Готовый пример

[Демо-магазин](https://itmo-workshop-09-11-2026.github.io/demo-shop/) показывает обязательный минимум: три товара, добавление, удаление и сумму. [Исходники демо](https://github.com/itmo-workshop-09-11-2026/demo-shop).

Проверка: добавьте блокнот за 100 ₽ и кружку за 200 ₽ — получите 300 ₽. Удалите блокнот — останется 200 ₽. Удалите кружку — будет 0 ₽. Сохранение корзины и оплата в демо не реализованы.

Организатор публикует демо подготовленным скриптом; до первого успешного запуска ссылка может возвращать 404.

## Если не использовали наш шаблон

Готовую статику можно публиковать из ветки:

1. Положите `index.html` и ресурсы в папку `docs/` ветки `main`, добавьте пустой файл `.nojekyll`.
2. В **Settings → Pages → Source** выберите **Deploy from a branch**, ветку `main` и `/docs`.
3. Сохраните настройки и дождитесь публикации. Изменения в этой папке после push будут публиковаться автоматически.

Выберите один способ: готовый workflow для `site/` либо публикация из ветки для `docs/`. Не смешивайте их настройки.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Нет кнопки Run workflow | Файл pages.yml отправлен в основную ветку; Actions разрешены в репозитории и организации |
| Workflow красный | Откройте упавший шаг и покажите текст ошибки ментору; проверьте Source: GitHub Actions |
| 404 | Дождитесь окончания деплоя; проверьте index.html в site/ и адрес из Settings → Pages |
| Нет стилей или картинок | Используйте относительные пути: `./styles.css`, `./assets/product.jpg`, а не `/styles.css` |
| Осталась старая версия | Проверьте commit/push и запуск workflow для нового коммита, обновите страницу без кеша |

## Проверка и откат

Ссылка открывается по HTTPS без входа. Работают добавление, удаление и общая сумма. Стили и используемые картинки загрузились. После обновления адрес сохранился. Если дополнительно реализовали сохранение корзины, проверьте его отдельно.

Для отката восстановите прежнее содержимое `site/` новым коммитом, отправьте его и повторите workflow. При публикации из ветки восстанавливайте `docs/`. Не переписывайте общую Git-историю.

Основной URL меняется вместе с сайтом и не является неизменяемой версией. Для воспроизводимости сдавайте commit ID и соответствующий ZIP.

Сайты разных репозиториев одной организации на `github.io` имеют общий origin. Если используете `localStorage`, добавляйте номер команды в ключ: `team07:cart:v1`. Это предотвращает случайные пересечения, но не даёт изоляции доступа между сайтами. Локальная корзина с localhost не переносится на публичный адрес.
