# Как работать с AI-агентом

Агент может написать код, но запускать приложение, проверять поведение и принимать решения должна команда. Один небольшой запрос и проверка обычно полезнее, чем просьба сразу сделать весь магазин.

## Первый запрос

```text
Мы делаем учебный интернет-магазин на трёхчасовом воркшопе.
Прочитай ТЗ из docs/task.md в репозитории гайда, если он доступен,
иначе попроси нас вставить текст. Сначала изучи наш проект.
Базовая версия должна работать как статический сайт без backend.
Предложи короткий план: 3 товара, добавление и удаление из корзины, общая сумма.
Сохранение, фильтры и промокоды добавляй только по нашей просьбе. Не добавляй платежи,
авторизацию и зависимости без необходимости.
Объясни, как запустить проект на нашей ОС и проверить первый результат.
```

Если агент не видит репозиторий гайда, передайте ему текст ТЗ. Упоминание пути само по себе не даёт доступа к другому репозиторию.

## Один цикл работы

1. Назовите конкретное поведение: «Добавь кнопку удаления товара из корзины».
2. Попросите показать, какие файлы меняются и почему.
3. Запустите сайт и проверьте обычный случай и границу: пустая корзина, удаление последнего товара.
4. Если результат работает, сохраните коммит с понятным названием.
5. Переходите к следующей функции.

## Запрос на исправление

Пример для команды, которая выбрала сохранение корзины как дополнительную задачу:

```text
Ожидали: после обновления страницы остаются два товара.
Получили: корзина пуста.
Шаги: открыть сайт, добавить два товара, обновить страницу.
Текст ошибки из консоли: <вставьте, если есть>.
Найди причину, исправь минимально и предложи проверку.
Не переписывай весь проект.
```

## Запрос перед публикацией

```text
Определи папку готового статического сайта и команду сборки,
если сборка нужна. Проверь относительные пути и отсутствие секретов.
Дай команды локального запуска и упаковки для нашей ОС.
Проверь, что в ZIP index.html окажется в корне.
Не создавай платные ресурсы и не меняй настройки аккаунтов.
```

Не передавайте агенту пароли участников и токены в тексте задач. Если секрет попал в публичный репозиторий, удаление строки недостаточно: отзовите секрет и сообщите ментору.

На демо каждый участник должен суметь объяснить хотя бы один свой сценарий: какие данные меняются, где они хранятся и как команда проверяла результат.
