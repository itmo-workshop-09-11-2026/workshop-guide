# Техническое задание для команды

## Что вы создаёте

Учебный магазин на выбранную тему: книги, настольные игры, космическая еда или что-то своё. Пользователь открывает сайт, выбирает товары и собирает корзину. Заказ и оплата не обязательны.

Обязательная версия работает в браузере на HTML, CSS и JavaScript. Можно использовать инструмент сборки, если команда умеет получать готовую статическую сборку. Go, Java, C# или Python могут обслуживать файлы локально или использоваться для дополнительного backend. Статический хостинг серверный код этих языков не запускает.

## Обязательный минимум

Достаточно одной страницы и трёх товаров. Если работают четыре пункта ниже, основная часть задания выполнена. Дополнительные функции можно вообще не делать.

| Функция | Как проверяем |
|---|---|
| Каталог | Не менее 3 товаров. У каждого есть название, цена в рублях и кнопка «Добавить» |
| Добавление в корзину | Выбранный товар появляется в списке корзины |
| Удаление из корзины | Товар можно убрать из корзины |
| Общая сумма | Сумма соответствует товарам в корзине и меняется после добавления и удаления. В пустой корзине — 0 ₽ |

Можно использовать целые цены без копеек. Повторное добавление разрешено сделать отдельной строкой или просто не добавлять товар второй раз — выберите удобный вариант. Счётчик количества не обязателен.

**Пример проверки:** добавьте товар за 100 ₽ и товар за 200 ₽ — итог 300 ₽. Удалите первый — итог 200 ₽. Удалите второй — корзина пуста, итог 0 ₽.

Достаточно работы в браузере на ноутбуке. Дизайн может быть простым, но названия, цены и кнопки должны быть понятны. Картинки, категории и мобильная версия не обязательны. После перезагрузки корзина может очищаться.

## Дополнительные задачи и соревнование

Обязательный минимум выше не меняется. После него можно развивать интерфейс, сделать backend или заняться качеством и публикацией. Не нужно выполнять весь список: выберите задачи, которые успеете показать работающими.

За дополнительные задачи начисляются баллы по [таблице оценивания](scoring.md). Максимум — 100 баллов вместе с обязательной частью. Для сравнения команд используется одна и та же таблица и финальная версия проекта.

### Интерфейс — до 30 баллов

Каждая задача стоит 3 балла. Точные проверки — в таблице оценивания.

| ID | Задача |
|---|---|
| F1 | Картинки товаров с подписями и заглушкой, если картинка не загрузилась |
| F2 | Изменение количества товаров в корзине с пересчётом суммы |
| F3 | Сохранение корзины после перезагрузки страницы |
| F4 | Поиск товаров по названию |
| F5 | Категории и фильтр с возможностью сброса |
| F6 | Сортировка по возрастанию и убыванию цены |
| F7 | Промокод на скидку 10% |
| F8 | Избранное с отдельным просмотром выбранных товаров |
| F9 | Удобная работа на телефоне |
| F10 | Основной сценарий доступен с клавиатуры |

Для сохранения используйте ключ `localStorage` с номером команды, например `team07:cart:v1`. При скидке 10% сумма 300 ₽ превращается в 270 ₽. Повторное применение кода не должно накапливать скидку.

### Backend — до 30 баллов

Можно использовать Go, Java, C# или Python. Выбирайте знакомый язык и любой удобный фреймворк. За сам выбор языка, количество библиотек и сложную архитектуру дополнительных баллов нет.

Каждая задача стоит 5 баллов:

| ID | Задача | Что сделать |
|---|---|---|
| B1 | API каталога | `GET /api/products` возвращает JSON с товарами, а страница загружает каталог из этого API |
| B2 | Поиск и фильтр на сервере | API принимает параметры поиска и категории; интерфейс отправляет их серверу и показывает результат |
| B3 | Создание заказа | `POST /api/orders` принимает ID товаров и количества, проверяет их и рассчитывает сумму на сервере |
| B4 | Хранение данных | Сохранить товары и заказы в SQLite или другой базе; данные остаются после перезапуска сервера |
| B5 | Остатки товаров | Заказ уменьшает остаток. Сервер не позволяет продать больше, чем есть, в том числе при одновременных запросах |
| B6 | Защищённое изменение каталога | Добавление или изменение товара через API доступно только с секретом организатора/администратора |

**Удобный порядок:** B1 → B2 или B3 → B4 → B5. B6 можно делать отдельно после B1. Сначала добейтесь рабочего запроса, затем подключайте интерфейс.

Минимальный ответ каталога:

```json
[
  { "id": "notebook", "name": "Блокнот", "price": 100, "category": "Канцелярия" },
  { "id": "mug", "name": "Кружка", "price": 200, "category": "Посуда" },
  { "id": "stickers", "name": "Стикеры", "price": 50, "category": "Канцелярия" }
]
```

Здесь `price` — целые рубли. Можно хранить цены в копейках, если это явно описано в README и правильно отображается в интерфейсе.

Пример запроса заказа:

```http
POST /api/orders
Content-Type: application/json

{"items":[{"productId":"notebook","quantity":1},{"productId":"mug","quantity":1}]}
```

Успешный ответ содержит ID заказа и сумму 300 ₽. Сервер получает цены из своего каталога: переданная клиентом заниженная цена не влияет на расчёт. Неизвестный товар, пустой список, отрицательное или дробное количество должны давать понятную ошибку 4xx, а не создавать заказ.

Для B6 достаточно учебного административного токена в переменной окружения и заголовке запроса. Проверяйте его через curl/Postman или серверный инструмент: **не встраивайте токен в публичный JavaScript**. Реальная регистрация пользователей, персональные данные и платежи не нужны.

### Как показать backend

Backend можно продемонстрировать локально и получить все баллы B1–B6: публичный сервер не обязателен. В README укажите версии инструментов, установку зависимостей, команды запуска, адрес API и способ подготовки тестовых данных. Приложите `.env.example` с пустыми значениями вместо секретов.

GitHub Pages публикует только статику и **не запускает backend**. Для локальной проверки удобно отдавать сайт и API с одного сервера. Если адреса разные, явно настройте адрес API и CORS. Если решили публиковать backend отдельно, фронтенд на HTTPS должен обращаться к HTTPS API, а не к `localhost`.

Для сдачи сохраните самостоятельную статическую версию обязательного минимума в ZIP: она должна работать без API. Это может быть отдельная демо-сборка с тестовыми товарами. Backend сдавайте исходниками и инструкцией; серверные функции ментор проверяет отдельно.

### Качество и деплой — до 20 баллов

- Q1: автоматические тесты функций магазина — 5 баллов.
- Q2: воспроизводимый запуск по README — 5 баллов.
- D1: публичный сайт по HTTPS — 5 баллов.
- D2: автоматическое обновление сайта после push в `main` — 5 баллов.

Собственный домен, необычная идея, оформление и дополнительные функции вне списка можно показать в демо. Они не меняют балльную таблицу; ведущий может отметить их отдельной номинацией.

## Что передать

Исходный код, README с запуском, ZIP готового сайта и краткий список реализованных функций. Публичная ссылка добавляется при выполненном деплое. Подробности — в [чек-листе](submission.md).

Не копируйте секреты и `.env` в публичные файлы. Любое значение в JavaScript браузера доступно посетителю. Используйте вымышленные товары и изображения, которые разрешено публиковать.
