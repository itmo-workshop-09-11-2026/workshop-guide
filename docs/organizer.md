# Памятка организатору

## Что изменилось в формате

Централизованный ZIP-сервис, общий сервер, выдача кодов, админка и нагрузочный тест 20 публикаций больше не входят в подготовку. Команды размещают сайты самостоятельно; локальная демонстрация и ZIP остаются запасным способом сдачи. Регистрация одного участника команды на хостинге допустима для дополнительного задания.

## До начала

- Опубликуйте этот репозиторий как `workshop-guide` в GitHub-организации.
- Проверьте доступность трёх template-репозиториев по ссылкам в README и зелёный результат workflow Check starter. Исходники и проверки шаблонов находятся в отдельных репозиториях.
- Для каждого шаблона проверьте запуск и упаковку на доступных ОС; в README укажите требуемую версию SDK. Docker и Make оставьте необязательными удобствами.
- Сохраняйте команды из регистрации. Канал сдачи — issue по форме в workshop-guide, одна на команду и дату; ZIP прикладывается к issue. Если вложение слишком большое, его принимает ментор.
- Проверьте из сети площадки доступ к GitHub и выбранному хостингу. Пройдите публикацию маленького сайта, обновление и открытие с другого устройства.
- Если используете GitHub Pages внутри одной организации, напомните про общий origin и ключи хранилища с номером команды.
- Предложенные в гайде достижения не имеют числовых весов. Если нужны баллы, объявите их до начала работы.

## Менторы

На 20 команд и 4–5 менторов назначьте по 4–5 команд каждому. Сначала помогайте с локальным запуском и основной функциональностью, потом с публикацией. Если сервис недоступен или регистрация затянулась, переключайте команду на запасной вариант через 10 минут.

При загрузке за команду используйте аккаунт ментора или организатора с разрешённым доступом. Не просите пароль студента. Укажите в отчёте, кто управляет проектом после мероприятия. Для повторяемого деплоя сохраните ZIP и инструкцию.

## После мероприятия

Соберите исходники, commit ID и готовые архивы. Для будущей автоматической проверки опирайтесь на сохранённую сборку: основной URL может измениться, а бесплатный проект — стать недоступным. Не обещайте студентам фиксированный срок доступности чужого хостинга.

## Публикация самого гайда

На компьютере с установленным GitHub CLI выполните из корня `workshop-guide` после входа в нужный аккаунт и проверки прав организации:

```bash
gh auth login
gh repo create ORG/workshop-guide --public --source=. --remote=origin --push
```

Замените `ORG` на реальную организацию. Команда предполагает, что локальный репозиторий уже содержит коммит, а удалённый репозиторий ещё не создан. Если GitHub CLI отсутствует, создайте пустой репозиторий в браузере и выполните показанные GitHub команды для существующего локального репозитория.
